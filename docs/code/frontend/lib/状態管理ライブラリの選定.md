# 状態管理ライブラリとは
useStateでお馴染みのStateをより効率よく管理するライブラリです。
一般的なメリットとして以下のものが挙げられています。

- Prop Drilling（propsのバケツリレー）問題の解消
- 可読性・保守性が向上する
  - setStateが絡む処理を一元管理できるため。

# 適用範囲
ピクセルエディタに限定して導入しようと考えています。

試しに"setPixelColorState"というワードでディレクトリを検索すると、以下がわかります。
1. propsの中にやたら出てくる（いわゆるProp Drillingが起こっている）
2. setPixelColorStateが色々なところで使われている
3. 同じような文脈で書かれた表現が重複している。
具体的には、以下の表現が色々なところで見られます。
```ts
  const updatePixelState = useCallback((x: number, y: number) => {
    const newState = [...pixelColorState]
    newState[y] = [...newState[y]]
    newState[y][x] = selectedColor
    setPixelColorState(newState)
    return newState
  }, [selectedColor, pixelColorState])
```

ReactのContext APIでもProp Drillingは解決できそうですが、
2番目及び3番目の解決には直接繋がらないですし、今までとは違うsetStateの使われ方が出始めた時に保守性が落ちる可能性があります。

イメージとしては、以下のようにリファクタできれば理想です。

BEFORE:
```ts
// hooksの呼び出し側
const circleDraw = useCircleDraw({
  canvasRef,
  numPixel,
  selectedColor,
  setPixelColorState,
  pixelColorState,
  setCircleColorState,
  circleColorState,
  textState
})

//　Propsの定義部
interface Props {
  canvasRef: React.RefObject<HTMLCanvasElement | null>
  numPixel: number
  selectedColor: Color
  setPixelColorState: React.Dispatch<React.SetStateAction<(Color | null)[][]>>
  pixelColorState: (Color | null)[][]
  setCircleColorState: React.Dispatch<React.SetStateAction<(Color | null)[][]>>
  circleColorState: (Color | null)[][]
  textState: TextState[]
}

// 色の更新部
const updatePixelState = useCallback((x: number, y: number) => {
  const newState = [...pixelColorState]
  newState[y] = [...newState[y]]
  newState[y][x] = selectedColor
  setPixelColorState(newState)
  return newState
}, [selectedColor, pixelColorState])
```

AFTER:
```ts
// hooksの呼び出し側
const circleDraw = useCircleDraw({
  canvasRef,
})


// propsの定義
interface Props {
  canvasRef: React.RefObject<HTMLCanvasElement | null>
}

// stateの更新部分
const updatePixelState = useCallback((x: number, y: number) => {
  updatePixelColorWithIndex(x, y, selectedColor) // Stateの変更を別の名前で定義できる

```

# 使用するライブラリ
暫定で"Jotai"にしようと思います。
主な理由としては以下の通りです。
- あくまでContextAPIの代替として考えており、ステートマシンみたいなことをしたいわけではない
  - JotaiのHPでもContextAPIの代替程度であればJotai > Zustandと書かれている
  - ただし、Jotaiはシンプルな記述や拡張性があり、ピクセル描画の用途に適していると考えています。
  - XStateもステートマシン的なものを意識しており、ピクセル描画とは関係なさそう
- 様々な拡張が存在しており、よりシンプルな記述で効率的な動作が可能かもしれない
  - useReducerAtom (Stateの変更関数にエイリアスをつけられる)
  - Immer (直接に変数を変えるような記述をしても、atomicな動作が保証される)
- 今のところ、高頻度でメンテされている
- 老舗のReduxよりもシンプルに書けるらしい

# 懸念点
ピクセル描画のパフォーマンスが落ちる可能性があります。
どう頑張ってもパフォーマンスが悪化しそうであれば、contextAPIを使用する(or 何もしない)方向で進めます。
